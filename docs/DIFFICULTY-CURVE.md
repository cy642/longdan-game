# 四章难度曲线 · 0.8.0

更新：2026-10-26。当前实现用攻击起手机会与整套招式之后的休息，让长坂教学留出更多观察空间，之后逐区收紧。它已通过自动调度检查，仍需完整普通难度实玩校准；参数顺序正确不等于难度体验已经定稿。

## 参数职责

权威配置为 [combat_pacing.gd](../godot/scripts/combat_pacing.gd)。`world.gd` 持有一个区域共用实例；普通敌人在距离、冷却、攻击人数等原有条件都满足后，才请求一次新招式起手。成功者占用一次间隔，其余敌人继续走位或等待。这里控制的是**一整套招式的开始**，不是每次挥刀、每颗箭或每段连击。

整套动作结束之后，再设置本表的额外休息。原招式自己的 `windup/active/recovery` 不改；双刀、双发弩和首领连段在内部继续衔接，不重复请求起手、不插入额外休息。原同屏两名近战和一名远程的限制继续有效；箕谷/陈仓箭阵与普通远程共享攻击机会，箭阵不走这个普通起手计时器。

本轮没有上调已有敌兵或旧将领的生命、伤害，也没有改变追踪锁向、命中窗口、闪避或盾防。新第四章都尉独立设定为普通难度生命 1500、破势 145；不能把它描述成旧首领数值完全不变的一个例子。

## 调用和存档边界

- `configure(stage, difficulty)` 在入区/重试时设置当前参数并清空计时，首次普通起手可用。未知测试区域保守采用山道值。
- `advance(dt)` 只由世界正常游玩的物理帧推进一次；暂停、军图、对话、营火、失焦暂停、死亡和命中停帧不推进。负数不倒流，非有限数不推进。
- `claim()` 同一物理帧最多成功一次；长帧不会积攒多个可瞬间消费的攻击名额。没有新增存档字段，读档不会继承隐藏的欠账。
- `post_chain_rest(kind, boss_id)` 仅用于一整套结束后的冷却；连段尚未结束时继续原衔接。不要在 `start_action` 或递归连击内部再次申请名额。
- 路线变化靠固定队伍与掩体调整压力。陈仓正门/侧巷分别削弱瓮城重盾/弩兵，提前取得调令阻止未到援军；不叠加未说明的全章生命或伤害倍率。

后续实玩记录应按章节、难度、路线、设备和耗时分别记录：第一波是否看得懂、多久有一次安全还击、是否长时间站着等、远程与箭阵是否叠压、死亡后是否恢复正确。先查名额是否按整套计算和暂停是否冻结，再针对具体遭遇调参；不要通过删掉原视觉/命中断言或凭帧率数字宣称难度已校准。
