# 三章敌军与将领美术规范

日期：2026-10-25。目标是让长坂追兵、汉水营军、箕谷山阵和四名敌将拥有独立的完整角色原画，能靠人体轮廓、兵器和站姿辨认，而不依赖换色、换披风或在旧身体上继续叠装备。

本页记录已经登记到 `godot/scripts/enemy_roster.gd` 的 **18 个兵卒 profile＋4 个将领 profile**、现有关卡配置及制作契约。新的图像交付和实际验收结果另记于 [开发记录](../CLOUD-POLISH.md)，不能仅凭 profile 已登记便声称原画、动画或发布已全部通过。

## 本轮范围与玩法边界

- 三章各使用五种现有非 Boss 行为，再各增加一个确实出场的区域专属美术身份，共十八种兵卒形象。不会为凑数量向地图添加不存在的敌人。
- 保留 `kind`、`boss_id`、HP、伤害、命中范围、前摇/生效/收招、碰撞半径、盾防、两发弩、有限波次和存档。新名字和画像不是额外职业技能。
- 每张新原画自带头部、身体、双腿和完整武器。新美术启用时不再叠加旧 `EnemyEquipment` 的第二把刀、弩、铁盾、督军钩斧或先锋戟刃，也不靠旧染色制造区别。
- 动画继续使用现有连续网格姿态与左右镜像，关联真实攻击阶段；**不是八方向逐帧动画**，也不是每名敌人拥有新绘制的整套攻击帧。赵云、随军、医者和百姓不在本轮敌军替换范围。

## 图像与辨识契约

统一沿用赵云的精细 Q 版三国插画方向：头部略大、面部清楚、金属和布料分层、边缘干净，使用同一俯视三分之四镜头与光向。敌人可有不同体形和甲重，不能因为长枪、旗帜或头缨更高而让人体缩小。

每张角色应提供透明背景、完整双脚、完整兵器和充分边距。脚底接触点是唯一落地锚点；不在源图烘焙地面、矩形底板、文字或大面积投影，避免与游戏阴影重复。完整武器与握持手必须连贯，避免枪尖孤立、盾外又冒出另一把旧武器。

三个优先辨认层级：

1. **兵器轮廓**：单刃、长矛、弓、双刃、横弩、圆盾、宽盾/高盾一眼可分。
2. **人体和姿态**：精瘦追兵、低身斥候、弩兵侧身、重盾前倾、校尉宽站姿，不能只是同一张脸换衣服。
3. **章内身份**：头盔、背负、甲片布局和布料长度强化长坂溃军、汉水营军与箕谷山阵的主题。颜色辅助辨认，不能承担全部区别。

图集和 profile 需要分别记录裁切、脚底锚点、人体尺寸标定、脸部保护区域和刚性武器区域。当前 `height` 为展示尺寸参数，普通兵分布在 72–87、校尉 92、四名首领 100–112；按实际人体标定换算，不能用包含长兵器的整幅透明包围盒直接缩放。面部与长杆仍作为刚性部分跟随上身，腿部承担步态变化。

## 四名独立敌将

四位首领统一 `kind=boss`，分别按 `boss_id` 解析到 `enemy_commanders` 图集。不能再让夏侯恩与督军共用一张持剑身体，也不能只在张郃原画上补一个戟刃当作玄甲先锋。

| ID / 图集帧 | 首领与现有行为 | 独立画面要求 |
|---|---|---|
| `boss_xiahou` / `[0]` | 夏侯恩；双剑、重斩、转身横斩 | 青釭长剑与副手短剑，修长贵胄将领、窄腰甲与分叉短披风；两只手和两把剑均完整绘出 |
| `boss_zhanghe` / `[1]` | 张郃；三连突、长枪横扫、回身反刺 | 单杆细长枪、挺拔沉稳、长羽盔与侧披风；身形和面部独立，强调长枪而不是重戟 |
| `boss_dujun` / `[2]` | 铁面督军；钩拉、双轮斧、撼地与断锁追斩 | 厚重宽体、铁面、带钩重斧与铜环；钩斧握在原画手中，不保留旧持剑再外贴斧头 |

## 接入、存档和重试契约

`Enemy.configure()` 保存 `visual_profile`，通过 `EnemyRoster.resolve(chapter,stage,kind,boss_id,group_id)` 获取 `id/atlas/index/name/height`。章节优先从区域名前缀 `hs_`、`jg_` 判断，其余为长坂；不强依赖测试 ReviewState 上不存在的 `chapter` 属性。普通敌军也取得名字，现有 UI 显示时机由界面继续决定。

正式 `world.spawn_enemy()` 的顺序为：赋予 world/group → configure → add_child。区域专属条件因此能在首次创建网格之前确定。切图和失败重试会重新创建敌人；汉水退军恢复继续传入原 `kind`、名册 HP 和群组，再解析同一汉水家族。新 profile 不写进存档，不迁移名册、不重置支线，也不参与攻击分支。

部分视觉测试会直接设 `kind/boss_id` 后加入场景，不调用 configure；`ActorVisual` 在 profile 为空时必须能安全解析默认家族。不同原画需要不同的网格缓存键，至少包含图集帧或 profile ID；不能把旧身体的脸部保护矩形、长杆权重或排除区域直接复用于新角色。保持敌人对象身份稳定，切换章节时正常销毁并重建，避免在战斗中途按全局章节重新换皮。

交付验收应包括：十八区实际解析到预期 profile；两种区域弩手只在指定组出现；动态营门/营救/校尉与退军恢复得到正确完整画像；四将不共底图；脚锚、人体比例、脸部刚性、长杆连贯和旧装备不重影；死亡、破势、左右翻转与原攻击时窗一致。数值和状态回归、真实图形验收、Web/Windows 导出应分别记录，不能用一张原画板代替实机场景检查。

## 原生联系表验收入口

新图集生成并导入后，从仓库根目录运行：

```powershell
godot --path godot --script res://tests/enemy_roster_preview.gd -- --label=enemy-art-v1
```

该入口需要原生图形渲染器。它使用真实 World、Enemy.configure、ActorVisual 网格与 Enemy.start_action，停掉物理、世界输入、音频和场景更新，以内存 Campaign 隔离玩家存档。输出 1280×960 的 22 人联系表，三行各六兵、第四行四将，使用同一 1.30 展示倍率、中文名和脚底原点参考线。

每个新标签产生待机左向、步行、蓄势、出手、待机右向镜像五张 `.qa/enemy-roster-标签-状态.png` 与一份 manifest，记录每个人的 profile、实际图集、姿态、脚点与网格边界。已经存在任一同标签输出时拒绝覆盖；更换标签保留前后证据。脚本不临时绘制武器，缺少新图集时不能用旧原画回退伪装验收。生成这份工具本身不代表图形验收已经执行，实际运行结果由开发记录另行记载。
